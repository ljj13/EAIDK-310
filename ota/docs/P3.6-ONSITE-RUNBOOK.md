# P3.6-ONSITE-RUNBOOK — fail-safe backend activation (on-site only)

Every step below requires the operator physically present: serial console
(CH340, 1500000 8N1), power control, and the prepared rescue SD within
reach.  **Nothing in this file may run over Tailscale/SSH.**  The board's
boot chain is untouched until STEP 4.  Recommended session order maps to
`ota/docs/FLASH-PLAN-P36.md` (deep detail) and
`bootloader/u-boot-eaidk310/docs/{EMMC-RAW-REGION,BACKEND-COMPARISON,FAILSAFE-BOOT}.md`.

Artifacts (PC-side, recomputed on-site before STEP 4; mismatch → STOP):

| Artifact | SHA-256 |
| --- | --- |
| `failsafe-raw/u-boot-dtb.bin` (candidate B, primary plan) | `427f24028ec49242433d405e4109a537e35da1c59d1be7f96e237d80ef35743c` |
| `failsafe-raw/u-boot-initial-env` (candidate B) | `b6f468463d14de8ed2f1b95dc8f4c6ca47ef83823fe6f201aca962f211a4d589` |
| `failsafe-bootcount-fs/u-boot-dtb.bin` (candidate A, fallback) | `dee563aacfac048bd0f28f3f004168a11d99cb1a633f8e823f2162bb8ec7903f` |

General stop rule: any check fails → STOP at that step, do NOT improvise;
execute the step's 回滚动作 and reassess.

## STEP 1 — 串口验证存储映射

Commands (U-Boot interrupt at `bootdelay`, or from Linux before reboot):

```sh
mmc list
mmc dev 0; mmc info
# from Linux instead: cat /sys/block/mmcblk2/device/{name,cid}; cat /sys/class/block/mmcblk2/size
```

**预期输出**
- `mmc list` shows the eMMC (non-removable) and the SD controller; record
  which devnum is the eMMC.
- `mmc info`: capacity ≈ 7.28 GiB (7818182656 B), CID begins `d60103` and
  contains ASCII `HBD08G`.
- Linux side: name `HBD08G`, cid `d60103484244303847390e14d12f5655`,
  size `15269888`.

**失败停止条件**: eMMC is NOT dev 0 in U-Boot numbering, or CID/capacity
mismatch → candidate B must not be flashed as-is.
**回滚动作**: none needed (read-only). Branch: either rebuild candidate B
with corrected `SYS_BOOTCOUNT_RAW_DEVID`, or fall back to candidate A.

## STEP 2 — 备份当前 bootloader region

```sh
sudo dd if=/dev/mmcblk2 of=/var/lib/eaidk-ota/backups/uboot-region-8M-12M.img \
     bs=1M skip=8 count=4 conv=notrunc 2>/dev/null
sudo dd if=/dev/mmcblk2 of=/var/lib/eaidk-ota/backups/idbloader-0-8M.img \
     bs=1M skip=0 count=8 2>/dev/null
sudo dd if=/dev/mmcblk2 of=/var/lib/eaidk-ota/backups/tail-12M-16M.img \
     bs=1M skip=12 count=4 2>/dev/null
sha256sum /var/lib/eaidk-ota/backups/*.img
# then scp all three OFF the board to the PC
```

**预期输出**: tail hash equals the locked baseline
`870A69106ADD87429598171DD582FA9E215BF843F310C3EF761E5BB59C873902`
(proven remotely on 2026-10-01; if it differs, the baseline moved → STOP
and re-audit per `EMMC-RAW-REGION.md`).
**失败停止条件**: hash mismatch, unreadable sectors, or insufficient
space for backups.
**回滚动作**: nothing to roll back (read-only); copy failures → fix storage
before proceeding.

## STEP 3 — 检查 /boot filesystem 或 raw region

Primary plan (candidate B): confirm the two record sectors are clean.

```sh
sudo dd if=/dev/mmcblk2 bs=512 skip=25600 count=1 status=none | od -An -tx1 | head -2
sudo dd if=/dev/mmcblk2 bs=512 skip=30720 count=1 status=none | od -An -tx1 | head -2
```

**预期输出**: both all-zero.
**失败停止条件**: non-zero bytes → another user of the region exists →
STOP; re-run the `EMMC-RAW-REGION.md` audit before any write.
**回滚动作**: none needed.

Fallback plan (candidate A) instead checks:

```sh
dumpe2fs -h /dev/mmcblk2p1 | grep "Filesystem features"
```

metadata_csum present → execute the documented remedy
(`FLASH-PLAN-P36.md` §2 item 8: umount → e2fsck -f → tune2fs -O
^metadata_csum → e2fsck -f → mount → re-verify).  Any e2fsck error →
STOP; do not proceed with candidate A on a damaged /boot.

## STEP 4 — 刷 candidate

Prepare on the PC first: zero-pad the chosen `u-boot-dtb.bin`/`u-boot.itb`
artifact to exactly 4 MiB; scp to the board; verify SHA-256 on-board.

```sh
sudo dd if=u-boot-dtb.bin.padded of=/dev/mmcblk2 bs=1M seek=8 conv=fsync notrunc
sync
sudo dd if=/dev/mmcblk2 of=/tmp/readback.bin bs=1M skip=8 count=4 status=none
cmp /tmp/readback.bin u-boot-dtb.bin.padded && echo READBACK-OK
```

Artifact-type note (from `FLASH-PLAN-P36.md` §0): decide FIT
(`u-boot.itb`) vs raw (`u-boot-dtb.bin`) from the STEP 2 backup content;
flash the same type the board already carries.

**预期输出**: `READBACK-OK`; dd reports exactly 4 MiB copied.
**失败停止条件**: cmp mismatch, dd short write, or on-board hash ≠ PC hash.
**回滚动作**: `sudo dd if=backups/uboot-region-8M-12M.img of=/dev/mmcblk2
bs=1M seek=8 conv=fsync notrunc && sync` then re-verify readback vs the
backup hash.

## STEP 5 — 立即验证 U-Boot 能正常启动 stable 108

Cold boot, serial captured:

**预期输出**
1. New U-Boot banner; `version` at the interrupt prompt shows the
   failsafe build; `printenv` shows `bootlimit=1`, `altbootcmd=…`,
   `bootcmd=if test ${upgrade_available} -eq 1 -a ${bootcount_stored} -eq 1; …`,
   `boot_targets=mmc1 mmc0 …` unchanged.
2. Unarmed boot path: `bootflow scan` → extlinux default → **Debian
   6.12.108** login; no bootcount error spam.
3. Linux up: `ls /boot/eaidk-ota/` shows no bootcount.bin and (candidate
   B) record sectors still zero — **U-Boot must NOT have created any
   state on an unarmed system** (fail-closed proof on real hardware).

**失败停止条件**: no serial output (pre-console crash → maskrom recovery,
`FLASH-PLAN-P36.md` §6), bootloop, or wrong default kernel.
**回滚动作**: STEP 4's rollback dd; if U-Boot shell reachable,
`setenv bootcmd bootflow scan; bootflow scan` boots stable first, then
reflash the STEP 2 backup.

## STEP 6 — TEST A：known-good 111 one-shot

Per `ota/docs/REHEARSAL-PLANS.md` TEST A, using the candidate slot
mechanism that matches STEP 4's variant:

- candidate B: `sudo eaidk-bootstate arm --backend raw --raw-device
  /dev/mmcblk2 --allow-block-write --label 6.12.111-test`
  then stage `/boot/extlinux/extlinux-candidate.conf` (111 default) and
  reboot.
- candidate A: write `/boot/eaidk-ota/bootcount.bin` via
  `eaidk-bootstate arm` + the same candidate conf.

**预期输出**: boot 1 = `bootcmd(candidate)` on serial
(`BF`/`sysboot` lines + 111 kernel boots).  Interrupt/fail the candidate
(serial reset during boot) → boot 2 = `altbootcmd(stable)` → 108 boots.
`eaidk-bootstate inspect` shows bootcount rising and then the fallback
record (A: file `01 01 02 01`; B: seq+1 on the non-selected copy).
**失败停止条件**: boot 1 boots 108 (selection dead), boot 2 boots 111
again (fallback dead), or no counter movement.
**回滚动作**: `eaidk-bootstate clear …` (both variants) → verify next
boot is unarmed-stable; worst case STEP 4 rollback.

## STEP 7 — TEST B：坏 candidate 自动 rollback

Arm a deliberately broken candidate (candidate conf pointing at a
nonexistent kernel), boot:

**预期输出**: every candidate attempt increments the counter; after
`bootlimit` is exceeded the board lands on `altbootcmd(stable)` → 108,
and *stays* on 108 for subsequent boots until cleared.
**失败停止条件**: more than one consecutive attempt of the broken
candidate (counter not persisting), or fallback not engaging.
**回滚动作**: clear bootstate; if the counter mechanism itself is broken,
STEP 4 rollback and STOP the rollout (backend = NOT verified).

## STEP 8 — 启用 BACKEND marker

Only after STEP 5–7 are all green:

```sh
# candidate B:
printf 'RawBootstateBackend 1\n' | sudo tee /boot/eaidk-ota/BACKEND
# candidate A:
printf 'BootcountFsBackend 1\n' | sudo tee /boot/eaidk-ota/BACKEND
sudo /usr/local/sbin/eaidk-ota status        # active: <name>, available: True
sudo cp eaidk-bootstate /usr/local/sbin/ && sudo chmod 755 /usr/local/sbin/eaidk-bootstate
```

**预期输出**: `eaidk-ota status` reports the active backend and live
bootstate; `authorize-local` works on ttyS2; `try` over SSH still refuses
(exit 3/4 as designed).
**失败停止条件**: status shows NoBackend (marker content mismatch).
**回滚动作**: remove the marker (board returns to NoBackend; boot chain
unaffected).

## STEP 9 — REMOTE_OTA_ELIGIBLE=YES

Only when ALL of the following hold: STEP 4–7 green, STEP 8 marker active,
TEST A and TEST B repeated once more end-to-end via `eaidk-ota`
(staged bundle → try → reboot → health → commit/rollback), operator still
on-site with serial+power.  Then — and only then — record
`REMOTE_OTA_ELIGIBLE=YES` in progress.md and update the frozen network
baseline memory.

**失败停止条件**: any health check degrades, any Tailscale lifeline wobble
during the rehearsal, or missing physical rescue capability.
**回滚动作**: keep/restore `REMOTE_OTA_ELIGIBLE=NO`; the boot chain is
already fail-safe at this point, but remote activation waits for a clean
full rehearsal.
