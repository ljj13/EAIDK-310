# P8.1 — 6.18.55 root cause & safe re-trial

Verdict first: **the 6.18.55 kernel was never broken.**  Candidate-1's
"hard hang ~4 s" was the kernel waiting forever for a root device whose
UUID does not exist on this board, hidden by `loglevel=4`, with no
watchdog because the first arm had already burned the only trial count
on a boot whose candidate conf was missing.  With the P8.1 trial
contract (candidate conf generated by `install-candidate`, APPEND taken
from the running stable entry, pre-arm consistency gate) the same
bundle — byte-identical kernel — boots to userspace and passes both
health gates.

## Evidence chain

1. **Contract fix (P1)** — `install-candidate` owns
   `extlinux-candidate.conf` (atomic, readback-validated, trial marker
   `eaidk_ota_trial=<release>@<bundle12>`); `arm` runs the ARM_ALLOWED
   checklist and refuses with the raw bootstate untouched on any gap.
   See [P8-TRIAL-CONTRACT-AUDIT.md](P8-TRIAL-CONTRACT-AUDIT.md).
2. **Known-good gate (P1.8)** — 6.18.54 installed/armed as candidate:
   serial shows `WDT: Started watchdog@ff1a0000 (30s timeout)` +
   `bootcount-raw: trial watchdog … rc=0` + candidate conf selected +
   cmdline marker; `CRITICAL_BOOT_HEALTH=PASS`, `REMOTE_HEALTH=PASS`.
   Rolled back without promotion.
3. **Config oracle (P2)** — A (6.18.54 good final config) ≡ B (6.18.55
   pipeline final) ≡ C (6.18.55 oracle: fresh upstream + board patch +
   A as seed + olddefconfig) — **zero functional symbol differences**
   (the 289-line diff was line-ordering noise).  `CONFIG_ROOT_CAUSE=REJECTED`.
4. **Decisive re-trial** — same 6.18.55 bundle, corrected conf:
   trial classification correct (WDT armed, bootcount 0→1), kernel booted
   to userspace, cmdline marker present,
   `CRITICAL_BOOT_HEALTH=PASS`, `REMOTE_HEALTH=PASS`.
5. **Upstream bisect (P3)** — `NOT_RUN`, and not needed: there is no
   kernel regression to bisect (range recorded anyway: v6.18.54
   `1b357ecb…` → v6.18.55 `725bd2f3…`, 395 commits, ancestry verified).

## Root cause

`STALE_TRIAL_CONF_ROOT_UUID` — the repo-rendered candidate APPEND
carried `root=UUID=bd2a6dbf…` (an old layout); this board's rootfs is
`781e1dc3…`.  Fixed structurally by P1.2: the trial conf inherits the
APPEND from the running stable entry, so board cmdline drift can never
break a candidate again.  A secondary latent gap (trial feeder unit is
the unapplied P3.7 template; kernel auto-ping covers the trial window)
is recorded for P8 follow-up.
