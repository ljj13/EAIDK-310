# P8 Trial Contract Audit

Audit of "who owns what" in the OTA candidate-trial chain before the P8.1
fixes, and the contract those fixes enforce.  Incident being addressed:
6.18.55 candidate-1 armed without `/boot/extlinux/extlinux-candidate.conf`,
burned the single trial count, and the real candidate boot was then
classified as a rollback (no watchdog) and hung waiting for a root UUID
that does not exist on this board.

## Ownership before P8.1 (gaps in bold)

| Artifact | Owner before | Gap |
|---|---|---|
| versioned Image/uInitrd/DTB | `eaidk-ota install-candidate` | ok (hash-verified, refuses different-content overwrite) |
| `/lib/modules/<release>` | `eaidk-ota install-candidate` | ok (P4 fix: full tree + marker + modules.dep gate) |
| bundle identity / trial marker | none | **no candidate identity existed**; a bare release string was the only label |
| `extlinux-candidate.conf` | **operator, by hand** | **not generated by any tool; missing ⇒ armed boot falls back to stable and burns the trial count** |
| candidate conf validation | none | **never parsed, never checked against installed assets** |
| root= UUID in trial cmdline | inherited from repo-hardcoded APPEND | **stale: `bd2a6dbf…` is not this board's rootfs (`781e1dc3…`); candidate waits forever in rootwait with loglevel=4 hiding the wait** |
| pre-arm consistency gate | none | **arm only checked the state machine, then mutated the raw bootstate** |

## Contract after P8.1

`install-candidate` (atomic, fail-closed):

1. installs versioned Image/uInitrd/DTB (hash-verified) and the full
   `/lib/modules/<release>` tree (marker + modules.dep gated);
2. generates `/boot/extlinux/extlinux-candidate.conf` from the **running
   stable default entry's APPEND** (so root=/console parameters always match
   the real board) plus versioned asset paths;
3. appends the trial identity marker
   `eaidk_ota_trial=<release>@<bundle_sha256[:12]>`;
4. fsync + rename + readback parse, validating label/LINUX/FDT/INITRD/marker
   against the installed files;
5. records `candidate_identity` (release, bundle sha, backend, marker,
   conf sha256, parsed fields) in the state store.

`arm` (fail-closed, read-only until every check passes) — the ARM_ALLOWED
checklist: candidate conf present / parseable / identity matches plan /
references expected Image, uInitrd, DTB / asset hashes match the staged
tree / module tree + modules.dep present / module release and install
marker match the candidate / trial marker present / candidate APPEND root
matches the stable entry / rollback target is the current stable default /
backend identity marker pass / raw bootstate currently safe (fresh or
armed-with-same-candidate).  Any failure prints `ARM_REFUSED (raw bootstate
untouched)` and exits **without writing the bootstate or incrementing the
sequence** — the trial count can no longer be burned by a half-prepared arm.

Candidate identity is `(kernel release, bundle sha256, conf sha256,
backend)` — never the version string alone, so candidate-1, candidate-2,
oracle and bisect builds cannot shadow each other.

## Regression coverage

`ota/tests/test_prearm_contract.py` (CASE 1–8): missing conf, wrong Image,
wrong uInitrd, wrong DTB, missing modules.dep, missing trial marker,
identity mismatch → each REFUSED; all-consistent → ALLOWED; plus a CLI
test proving a refused arm leaves the raw bootstate device byte-identical.

## Known pre-existing failures (not from this change)

`ota/tests/test_eaidk_backend.py` RawBackendFixtureTests cases fail
identically on the pre-P8.1 baseline (verified via `git stash` run);
they exercise the raw backend fixture paths and are tracked separately.
